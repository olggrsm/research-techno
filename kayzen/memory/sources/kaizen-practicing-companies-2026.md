# Источники: компании с явной кайдзен/lean-практикой в разработке ПО

- SenecaGlobal — материалы о применении Kaizen в разработке (billing-rate
  улучшения через agile + risk assessment, "Innovative Kaizen" для
  креативных процессных улучшений) — https://senecaglobal.com/
- Kreyon Systems — обзорная статья о применении Kaizen-подхода в
  software-командах — https://www.kreyonsystems.com/
- Общеотраслевые материалы (без единого первичного источника) о применении
  Lean software delivery в Amazon и Microsoft — упоминания общего характера,
  без конкретных внутренних кейсов
- Общеотраслевые материалы, использующие переход Netflix DVD-прокат →
  стриминг как иллюстрацию кайдзен-принципа "отказ от устаревшей практики"
  (не первичный источник от самого Netflix, интерпретация сторонних авторов)

Оговорка по достоверности: в отличие от Spotify/Amazon/Netflix/Google, для
направления "компании, явно практикующие кайдзен в software" не нашлось
сопоставимого по качеству первичного источника (инженерский блог, доклад,
книга от участников). SenecaGlobal — единственный найденный пример с
конкретным описанием практики, но источники вторичные
(маркетинговые/консалтинговые статьи, не независимый кейс-стади). Amazon и
Microsoft фигурируют в этом направлении лишь как общие упоминания "Lean
software delivery" без деталей и без пересечения с их собственными
первичными материалами (использованными выше в
`memory/sources/amazon-2026.md`). `confidence` для этого направления должен
быть `low`.

Ключевое: явных, хорошо документированных кейсов "компания X формально
внедрила кайдзен как метод разработки ПО и получила измеримый результат"
поиск не обнаружил. Зато широко распространены смежные паттерны, которые
индустрия связывает с кайдзен без использования самого термина: CI/CD как
воплощение короткого цикла обратной связи (аналог PDCA), Kanban-доски и
"Andon Cord"-аналогии (остановка работы при обнаружении дефекта в
спецификации), Gemba walks в контексте инженерных ретроспектив. Это
указывает на то, что кайдзен-терминология в software-индустрии используется
существенно реже, чем сами кайдзен-практики под другими названиями
(DevOps, continuous improvement, retro-driven process change).
