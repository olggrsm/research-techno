summary: >-
  Team Topologies (Skelton/Pais) выделяет 4 типа команд, где stream-aligned
  team — основной тип, выстроенный вокруг потока ценности для пользователя
  без передачи работы другим командам; остальные три типа (platform,
  complicated-subsystem, enabling) существуют для снижения когнитивной
  нагрузки на stream-aligned команды. Рекомендация по размеру — команды
  около 8 человек (число Данбара); при превышении 15 человек доверительные
  связи и координация деградируют, что напрямую увеличивает когнитивную
  нагрузку. В майском (2025) обновлении Team Topologies формализуют это
  через партнёрский инструмент Teamperature: сложность определяется как
  рост числа транзактных взаимодействий, нужных для координации, — чем
  больше и сложнее команда, тем больше нагрузки. 2026-дискуссия: AI-агенты
  начинают выполнять функцию, исторически закреплённую за платформенными
  командами (снятие рутинной когнитивной нагрузки — boilerplate, поиск по
  коду, первый черновик реализации), и в отдельных AI-forward организациях
  компрессия работы концентрируется на одном старшем инженере с системным
  пониманием — что создаёт новый риск устойчивости темпа именно для этого
  человека, а не для команды в целом.

Связь с кайдзен: явное признание предела когнитивной нагрузки человека и
команды перекликается с muri ([[memory/facts/muri/definition]]) —
перегрузкой как одним из трёх видов потерь (3M), которую gemba-управление
целенаправленно устраняет. Team Topologies структурно решает ту же
проблему на уровне организационного дизайна, а не только процесса —
интересная точка для сравнительного анализа Этапа 4: кайдзен фокусируется
на выявлении и устранении muri через наблюдение и стандартизацию, Team
Topologies — через архитектуру команд.
