# Тезис

Для документа «Видение»: практика надёжности/устойчивости не должна
оцениваться только по итоговому результату (resilience, MTTR, throughput),
но обязана также оцениваться по критерию muri
([[memory/facts/muri/definition]]) — не создаёт ли она хронической
перегрузки людей. Практика, дающая сильный измеримый результат за счёт
устойчивой перегрузки команды, не может быть рекомендована документом
«Видение» как образец без этой оговорки.

# Обоснование

Netflix Chaos Engineering ([[memory/insights/netflix-2026]]) даёт сильный
результат по устойчивости инфраструктуры, но 2025-критика описывает
культуру, обеспечивающую этот результат, как "unforgiving"/подверженную
выгоранию. DORA 2025 фиксирует структурно похожий эффект в другой форме:
рост throughput через AI-adoption сопровождается ростом нестабильности
("быстрее, но не лучше", [[memory/insights/dora-metrics-2026]]) — то есть
локальная оптимизация одной метрики без внимания к muri/mura в остальной
системе даёт нестабильный, а не устойчиво воспроизводимый результат.
Google SRE ([[memory/insights/google-2026]]) отдельно вводит error budget
именно как формализованный противовес этому риску — что показывает: сам
принцип "не-muri как ограничение" уже частично признан индустрией, просто
не под кайдзен-именем.

# Статус

`proposed` — требует явного review. Ограничение: критика Netflix-культуры
2025 года — качественная (интервью, кейс-стади), не количественное
измерение выгорания; связь между "unforgiving culture" и конкретными
показателями текучести/burnout не подтверждена количественно в найденных
источниках.
