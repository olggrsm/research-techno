# Удаление старых данных из истории без потери целостности

История не удаляется строками: удаление по одной строке ломает ссылочную целостность проекций и делает невозможным восстановление на момент до удаления. Вместо этого — партиционирование по времени и отсечение целых партиций.

Таблицы истории и событий партиционируются по дате (день или месяц, в зависимости от потока); retention выражается как «держать N партиций», а удаление — `DROP PARTITION` старше границы. Снимок состояния (snapshot) агрегата создаётся до отсечения, чтобы replay после границы начинался со снимка, а не с самого первого события. Ссылки на удалённое заменяются на tombstone-записи, а не исчезают молча.

Границы retention задаются по классу данных: K-факты — не меньше срока, за который строится аудит; персональные данные — по требованию их удаления, с обезличиванием в снимке.
