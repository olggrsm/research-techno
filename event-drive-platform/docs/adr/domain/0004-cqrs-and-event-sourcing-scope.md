# CQRS и Event Sourcing: где применяем, а где нет

Event Sourcing применяется там, где нужен полный аудит и восстановление состояния из событий: финансовые операции, резервирования, изменения статусов с длинной историей. Во всех остальных местах — обычное состояние в БД с публикацией факта через transactional outbox; шина не обязана быть источником истины.

Где ES применяется, поток событий агрегата — источник истины, а проекции (read models) строятся отдельно и отстают, что даёт eventual согласованность чтения; модель согласованности каждый класс данных объявляет явно (R-11). Команды идут на запись, запросы — в проекции; это разделение и есть CQRS.

**Отвергнуто:** ES «по умолчанию» для всех сервисов — история растёт без ограничений, восстановление проекций становится обязательным операционным процессом, а выгода есть только там, где аудит и replay действительно нужны.
