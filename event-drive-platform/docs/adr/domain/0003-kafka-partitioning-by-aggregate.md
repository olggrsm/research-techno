# Партиционирование Kafka по агрегатам

Порядок в Kafka существует только внутри партиции, а требование домена — порядок по объекту. Поэтому ключ партиционирования — `aggregate_id`: все события одного агрегата попадают в одну партицию и применяются последовательно, а порядок между агрегатами не обещается.

Число партиций берётся по потоку: для K-команд N3 (около 10 000/с) — из расчёта пропускной способности партиции на целевом железе при подтверждении после локального fsync; для K-фактов (около 100 000/с) — отдельный топик и своё число партиций. Расширение партиций меняет соответствие ключей партициям, поэтому число выбирается с запасом на весь горизонт роста, а не по текущей нагрузке.

**Отвергнуто:** ключ по `correlation_id` — один корреляционный идентификатор объединяет несколько независимых событий и не даёт порядка по объекту; глобальный порядок между партициями — не достигается и домену не нужен, упорядочивание идёт версией агрегата.
