# Bi-temporal история и запросы на момент времени

Домену нужны два независимых времени: когда факт произошёл в предметной области (`occurred_at`, ось valid time) и когда он записан в систему (ось transaction time). Платформа обязуется сохранять `occurred_at` и HLC-метку в конверте и не переписывать событие; таблицы с периодами действия строит доменный сервис.

Периоды задаются как `[valid_from, valid_to)` и `[recorded_at]` с монотонным `sys_version`, а не с `updated_at`: монотонный счётчик не зависит от часов и даёт однозначную последовательность. Текущая строка — та, у которой `valid_to` в будущем; закрытие периода и открытие следующего идут одной транзакцией, чтобы запрос на момент времени не увидел разрыв.

Запрос «состояние на момент T» — фильтр по `T >= valid_from AND (T < valid_to OR valid_to IS NULL)` по обеим осям, если нужен точный срез с учётом поздних исправлений.
