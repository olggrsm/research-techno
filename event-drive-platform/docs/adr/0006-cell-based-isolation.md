# Ячеистая изоляция отказов

## Context and Problem Statement

Требование D-3 — делить платформу на ячейки без общего состояния, чтобы отказ ограничивался радиусом ячейки. Без этого плохой релиз или poison pill в общем кластере останавливает всё развёртывание сразу, а multi-AZ защищает только от отказа зоны. Каким должен быть размер ячейки и как связаны ячейки между собой?

## Decision Drivers

* Радиус отказа ограничен и известен заранее (D-3).
* Выкат волнами через canary-ячейки (D-5).
* Маршрутизатор между ячейками без состояния (D-4).
* Ограничение операционной стоимости: слишком мелкие ячейки дороже в эксплуатации.

## Considered Options

* Единый кластер с multi-AZ.
* Ячейки размером 1/20 парка (5% в худшем сценарии).
* Ячейки размером 1/100 парка.

## Decision Outcome

Chosen option: «Ячейки размером 1/20 парка», потому что оно даёт приемлемый радиус отказа при умеренной операционной нагрузке.

У каждой ячейки свой кластер и своя цепочка развёртывания, состояние одной ячейки недоступно другой. Маршрутизатор между ячейками stateless и продублирован (D-4). Выкат идёт волнами через canary-ячейки (D-5): дефект сначала останавливает одну ячейку, а не всю платформу.

### Consequences

* Good, because отказ одной ячейки затрагивает не более 5% парка.
* Good, because poison pill и плохой релиз ограничены ячейкой.
* Bad, because зависимости между ячейками недопустимы, а миграции — её основной источник; миграции проектируются как обратно совместимые шаги по ячейкам.
* Bad, because нужна автоматизация развёртывания, иначе волновой выкат превращается в ручную работу.

### Confirmation

Тест blast radius: отказ одной ячейки под нагрузкой — доля недоступных клиентов не выше расчётной. Проверка отсутствия общего состояния — негативный тест доступа к данным чужой ячейки.

## Pros and Cons of the Options

### Единый кластер с multi-AZ

* Good, because проще эксплуатация и меньше инфраструктуры.
* Bad, because защищает от отказа зоны, но не от плохого релиза и poison pill.

### Ячейки 1/20

* Good, because ограничивают радиус до 5% при умеренной стоимости.
* Neutral, because размер можно пересмотреть по фактическому числу клиентов.
* Bad, because требует обратно совместимых миграций по ячейкам.

### Ячейки 1/100

* Good, because меньший радиус поражения.
* Bad, because операционная нагрузка кратно выше.
