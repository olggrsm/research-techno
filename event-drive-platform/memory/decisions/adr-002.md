# ADR-002: Подтверждение K только после fsync и репликации ×3 по доменам отказа

**Статус:** предложено

## Решение

Для событий K подтверждение выдаётся после локального fsync на зеркале; NATS настраивается `sync_interval: always`, Kafka flush явно; режим по умолчанию не принимается без fault-injection проверки.

## Альтернативы

- Lazy fsync с опорой на репликацию: уязвим к коррелированным отказам (Jepsen NATS 2.12.1)
- Кворумная запись без локального fsync

## Последствия

- Рост p99 при fsync-per-ack
- Остаточный риск: потеря узла до репликации теряет K (принят заказчиком)
