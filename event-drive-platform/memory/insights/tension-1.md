# Напряжение 1: Долговечность и задержка

Заголовочные цифры брокеров обычно получены без fsync перед подтверждением. Независимый анализ Jepsen для NATS 2.12.1 (8.12.2025) [О] показал: при повреждении или усечении файлов на меньшинстве узлов потеряно 679 153 подтверждённых записи из 1 367 069 в одном прогоне; при скоординированном отказе питания или падении ОС на одном узле в сочетании с паузами и разделениями теряются подтверждённые записи и возникает устойчивый split-brain. Причина (по крайней мере частично) — flush на диск раз в две минуты вместо fsync перед подтверждением. Окна потерь по порядку величины совпадали с `sync_interval` (10 с в тестовом прогоне).
