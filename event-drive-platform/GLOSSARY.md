# Event Drive Platform

Контекст требований к event-driven платформе: категории событий, классы узлов, живучесть при сетевых ограничениях.

## Language

**Событие**:
Неизменяемая запись о случившемся или о требуемом действии, публикуемая в шину.
_Avoid_: сообщение, пакет, запись

**K-команда**:
Событие, адресованное владельцу объекта и требующее изменения его состояния; исполняется однократно и имеет срок актуальности.
_Avoid_: критичное событие, команда K, приказ

**K-факт**:
Доменное событие о свершившемся изменении состояния, публикуемое владельцем для всех подписчиков без адресата.
_Avoid_: событие K, состояние, состояние переносом

**E**:
Событие, потеря которого допустима: телеметрия, диагностика, уведомления без изменения состояния.
_Avoid_: некритичное событие, прочее событие

**Владелец объекта**:
Узел, на котором размещён шард объекта; только он применяет K-команды к объекту и публикует его K-факты.
_Avoid_: лидер, primary, мастер

**Шард объекта**:
Подмножество объектов, привязанное к одной партиции и одному узлу-владельцу.
_Avoid_: партиция, сегмент, диапазон ключей

**Версия агрегата**:
Монотонный номер состояния объекта, по которому событие применяется только если его версия больше текущей.
_Avoid_: версия события, счётчик изменений

**valid-until**:
Момент, после которого K-команда не исполняется, а переводится в явный исход «просрочена».
_Avoid_: TTL, срок жизни, срок годности

**Исход команды**:
Зафиксированный результат K-команды: исполнена, отклонена исполнителем или просрочена.
_Avoid_: статус, результат обработки
